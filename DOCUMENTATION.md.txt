# SENTINEL — Technical Documentation

## 1. Project Overview

SENTINEL is an intelligent digital threat monitoring and security analysis platform designed to analyze URLs, domains, and IP addresses and provide a structured security assessment.

The system combines a web-based security operations interface with a FastAPI backend and SQLite database. Users can submit a digital target, run an analysis, review detected security indicators, receive a normalized threat score, and access previous scan results.

SENTINEL is designed as an educational and portfolio-oriented security analysis platform. Its purpose is to demonstrate practical concepts such as web application development, API communication, security heuristics, threat scoring, database management, and responsive interface design.

---

## 2. Project Objectives

The main objectives of SENTINEL are:

* Analyze suspicious URLs.
* Analyze domains and IP addresses.
* Detect potentially suspicious characteristics.
* Convert detected indicators into a threat score.
* Categorize targets into LOW, MEDIUM, HIGH, or CRITICAL risk levels.
* Store completed assessments in a SQLite database.
* Provide a scan history for previous assessments.
* Present security information through a professional dashboard.
* Maintain communication between the frontend and FastAPI backend.
* Provide a foundation that can be expanded with more advanced threat-intelligence capabilities.

---

## 3. System Architecture

SENTINEL follows a simple three-layer architecture.

### Frontend Layer

The frontend provides the user interface and contains:

* Dashboard
* Threat Scanner
* Scan History
* Intelligence Center
* Target selection
* Scan result visualization
* Loading and error states
* Backend status monitoring

Main frontend technologies:

* HTML5
* CSS3
* JavaScript

### Backend Layer

The backend is implemented using FastAPI.

The backend is responsible for:

* Receiving analysis requests.
* Validating request data.
* Performing URL analysis.
* Performing domain and IP analysis.
* Calculating threat scores.
* Generating recommendations.
* Saving scan results.
* Returning scan history.

Main backend technologies:

* Python
* FastAPI
* Pydantic
* SQLite

### Database Layer

SENTINEL uses SQLite for persistent scan storage.

The database stores:

* Scan ID
* Target
* Target type
* Risk score
* Risk level
* Recommendation
* Creation timestamp

## 7. Database

SENTINEL uses SQLite because it provides a lightweight persistent database without requiring a separate database server.

The primary table is:

### scans

| Column         | Purpose                           |
| -------------- | --------------------------------- |
| id             | Unique scan identifier            |
| target         | Analyzed target                   |
| target_type    | URL, domain, or IP                |
| risk_score     | Numeric score from 0 to 100       |
| risk_level     | LOW, MEDIUM, HIGH, or CRITICAL    |
| recommendation | Generated security recommendation |
| created_at     | Scan creation timestamp           |

The database is automatically initialized when the FastAPI application starts.

## 8. URL Analysis

SENTINEL evaluates several characteristics of a submitted URL.

### HTTPS Detection

URLs that do not use HTTPS receive a security penalty because unencrypted HTTP communication can expose transmitted information.

### Suspicious Keywords

The system checks for potentially sensitive keywords such as:

* login
* signin
* verify
* verification
* account
* password
* secure
* confirm
* bank
* wallet
* payment

The presence of multiple sensitive keywords can increase the threat score.

### URL Length

Unusually long URLs can increase the score because excessive URL length may sometimes be associated with suspicious or deceptive links.

### Subdomain Analysis

URLs containing a large number of subdomains can receive an additional security indicator.

### Embedded Credentials

The system checks whether authentication information is embedded directly within the URL.

### Direct IP Address

The system can identify when a URL uses an IP address instead of a traditional domain name.

---

## 9. Domain and IP Analysis

SENTINEL can analyze both domain names and IP addresses.

### Domain Resolution

For domains, SENTINEL attempts DNS resolution and records resolved IPv4 addresses.

### Domain Characteristics

The system evaluates characteristics such as:

* Hostname length
* Number of subdomains
* Hyphen usage
* DNS resolution status

### IP Classification

When an IP address is supplied, SENTINEL checks characteristics such as:

* Private address
* Loopback address
* Multicast address

These properties are returned as security indicators.

---

## 10. Threat Scoring

SENTINEL converts detected security indicators into a normalized score between 0 and 100.

The scoring engine uses severity weights.

| Severity | Weight |
| -------- | -----: |
| LOW      |      5 |
| MEDIUM   |     15 |
| HIGH     |     25 |
| CRITICAL |     40 |

The final score is limited to the range:

```text
0–100
```

This makes the result easier to interpret and display in the user interface.

---

## 11. Risk Classification

SENTINEL uses four risk categories.

|  Score | Risk Level |
| -----: | ---------- |
|   0–29 | LOW        |
|  30–59 | MEDIUM     |
|  60–79 | HIGH       |
| 80–100 | CRITICAL   |

### LOW

No major indicators were detected by the current analysis rules.

### MEDIUM

Suspicious characteristics were detected and additional verification is recommended.

### HIGH

Significant risk characteristics were detected and further investigation is recommended.

### CRITICAL

The target requires immediate investigation according to the current rule-based assessment.

---

## 12. Security Recommendations

After calculating the threat score, SENTINEL generates a recommendation based on the final risk level.

The recommendation is intended to help the user understand the significance of the result.

The recommendations are rule-based and should not be interpreted as a complete real-world security verdict.

## 14. Frontend ↔ Backend Communication

The frontend communicates with the FastAPI backend using HTTP requests.

The backend is expected to run on:

```text
http://127.0.0.1:8000
```

The frontend sends JSON requests to the analysis endpoint.

Example request:

```json
{
  "target": "https://example.com",
  "target_type": "url"
}
```

The backend processes the request and returns a structured JSON response containing the analysis and threat assessment.

---

## 15. API Communication Flow

The general scan workflow is:

```text
User enters target
        ↓
Frontend validates target
        ↓
Frontend sends API request
        ↓
FastAPI receives request
        ↓
Target analysis is performed
        ↓
Threat score is calculated
        ↓
Result is stored in SQLite
        ↓
JSON response returned
        ↓
Frontend displays result
        ↓
Dashboard/history is refreshed
```

## 20. Running SENTINEL

### Start the Backend

From the backend directory, run:

```bash
uvicorn main:app --reload
```

The FastAPI server will normally be available at:

```text
http://127.0.0.1:8000
```

### Start the Frontend

Open the frontend using a local development server.

For example, with a suitable local server, the frontend may be available at:

```text
http://127.0.0.1:5500
```

The frontend JavaScript configuration must point to the correct FastAPI backend address.

## 23. Limitations

SENTINEL currently uses a rule-based analytical engine.

It does not automatically represent a complete enterprise threat-intelligence platform.

For example, the current implementation does not inherently provide:

* Malware sandboxing
* Full packet inspection
* Commercial threat-intelligence feeds
* WHOIS intelligence
* Certificate reputation analysis
* VirusTotal-style multi-engine scanning
* Real-time global threat feeds
* Advanced machine-learning classification
* Full vulnerability scanning
* Automated penetration testing

These limitations are intentional for the current project scope.

## 25. Security and Responsible Use

SENTINEL should be used responsibly.

Users should only analyze targets that they are authorized to investigate or that are publicly available for legitimate security analysis.

The platform is intended for educational, defensive, research, and authorized security-analysis purposes.

A SENTINEL score is an analytical indication produced by the current rule set. It should not be treated as definitive proof that a target is malicious or safe.
